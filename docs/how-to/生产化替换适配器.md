# How-to：把本地样板替换为生产基础设施

本指南说明替换顺序，不声称仓库默认已经连接真实 DMS、WMS 或 LangSmith。

## 1. Repository：内存 → PostgreSQL

保持 `create/get/save/list` 契约，新实现至少需要：

- `service_request_id` 主键，`version` 乐观锁；
- JSONB 保存诊断、Task Plan 和时间线，或按审计要求拆表；
- `UPDATE ... WHERE id = ? AND version = ?`，影响行数为 0 时抛 `OptimisticLockError`；
- 工单写入与 Outbox 插入使用同一事务；
- 关键审批和库存写操作使用幂等键。

建议表：`service_request`、`work_order_event`、`approval`、`outbox_message`、`pii_subject`。PII 库应独立 schema/密钥和更严格审计。

## 2. LangGraph Checkpointer：MemorySaver → PostgresSaver

保持 `thread_id=service_request_id`。在应用启动时创建连接池并注入 checkpointer。需要特别处理：

- 图 schema 变更的向后兼容；
- 中断超过保留期后的人工迁移；
- resume 的幂等性；
- 工单版本与 checkpoint 版本不一致时拒绝继续。

## 3. 资源租约：字典 → Redis

使用 `SET resource:{id} {order_id} NX PX {ttl}` 建立租约；续租必须比较 value 后再延长，释放要使用 Lua compare-and-delete，避免误删新持有者的租约。

审批后若 Redis 预占成功、数据库审计失败，应立即释放；若释放失败，写补偿任务并告警。不能把 TTL 当作唯一释放机制。

## 4. Outbox：内存 → Kafka

在 PostgreSQL 事务中插入 outbox。Relay 可用轮询加 `FOR UPDATE SKIP LOCKED`，也可用 CDC。消费者以 `message_id` 去重。

推荐主题：

- `service_request.created`
- `diagnosis.confirmed`
- `dispatch.assigned`
- `parts.reserved`
- `diagnosis.mismatch`
- `workorder.closed`

分区键使用 `service_request_id`，保证同一工单事件有序；不要使用随机 message_id 做分区键。

## 5. Hybrid RAG：小语料 → 多存储

- OpenSearch：BM25、手册标题/章节、DTC/件号 keyword 字段。
- pgvector：段落向量、模型版本、embedding 版本。
- PostgreSQL：品牌、车型、年款、配置、手册生效/失效日期。
- Neo4j：故障—原因—检查项—配件—工具关系。

先执行结构过滤，再并行查询。所有结果必须带 `evidence_id` 和 `version`。索引更新采用蓝绿 alias，避免半更新状态。

## 6. MCP Gateway：本地 Principal → OAuth 2.1

API Gateway 验证 OAuth access token 的签名、issuer、audience、expiry；MCP Gateway 根据 subject、role、scope、tenant、region 和资源属性做二次授权。

敏感工具必须：

- 参数 schema 校验；
- 幂等键；
- 绑定工单版本的人工审批证明；
- 请求/结果摘要审计；
- 限流、熔断、timeout；
- 对 PII 和 token 脱敏；
- 不信任模型生成的 tool annotation。

## 7. LangSmith

设置 `LANGSMITH_TRACING=true`、`LANGSMITH_API_KEY` 和项目名，把本地 `service_request_id`、`plan_version`、`prompt_commit`、`domain` 作为 metadata/tag。不要发送原始手机号、车主姓名、精确地址或未脱敏图像。

Trace 树建议：

```text
root: service_request
├── parent_agent
├── maintenance_agent
│   ├── hybrid_retrieval
│   └── tool calls
├── parallel_fulfillment workflow
│   ├── dispatch_agent
│   └── parts_agent
└── closure workflow
```

## 8. 上线门禁

至少验证：状态机路径、重复请求幂等、审批不可绕过、跨租户/跨区域访问、改诊补偿、迟到回调、Outbox 重放、知识版本冲突、跨品牌证据泄漏、高压门禁、降级模式和手动接管。
