# 安全、可观测与评测

## 1. 风险模型

项目风险不只包括传统接口攻击，还包括 Agent 特有风险：

- Prompt injection 诱导越权工具调用；
- 模型伪造 DTC、件号或维修步骤；
- 跨品牌/车型检索污染；
- 重试造成重复建单、重复派工、重复扣库存；
- 对话或 Trace 泄漏手机号、车牌、精确位置；
- 模型把 What-if 或推断包装成事实；
- 自动知识回流污染检索库。

## 2. 纵深防御

### 输入层

Pydantic 校验长度、枚举和数值范围。VIN 还经业务工具验证。多模态文件在生产中要做 MIME、大小、恶意内容和 EXIF/PII 处理。

### 决策层

品牌/车型/HV 是硬规则；初诊始终需要专家；配件必须经过确诊；运营必须 metric_id 白名单。

### 工具层

MCP Gateway 不信任 Agent 自述权限。它重新验证 principal scope、参数、速率和断路器，敏感参数在审计中脱敏。

### 状态层

状态机禁止跳步，乐观锁拒绝旧版本覆盖，审批 token 阻止未授权写操作，Saga 处理跨系统部分成功。

### 知识层

结案案例先隔离、脱敏、质检和版本发布，不直接进入生产索引。

## 3. Trace 树

`TraceRecorder` 使用 ContextVar 保存当前 span，使 Tool 自动成为 Subagent/Workflow 的子节点。每个 span 记录：name、kind、span_id、parent_id、时间、状态、错误和 metadata。

关键 metadata：

- service_request_id；
- plan_version；
- prompt_commit（生产）；
- model/provider（生产）；
- knowledge_index_version；
- actor/role；
- tool risk。

日志只能用于定位“发生了什么”，不能替代审计。审计记录需防篡改、有保留策略和访问权限。

## 4. 评测分层

### 单步评测

- intent/route 准确率；
- DTC 和车型抽取；
- metric_id 映射；
- 工具参数 schema 通过率。

### 检索评测

- Recall@K；
- MRR/NDCG；
- CitationHitRate；
- 品牌/车型/版本泄漏率；
- 无证据回答率。

### 轨迹评测

- 必要审批是否出现；
- 工具顺序是否合规；
- 是否重复写；
- 并行 Join 是否完整；
- 失败是否进入补偿或人工接管。

### 最终输出评测

- Faithfulness；
- 证据引用完整性；
- 安全表达；
- 结构 schema；
- 专家可执行性。

### 业务不变量

这是最重要的一层：不重复建单、不绕过审批、无确诊不扣库存、改诊不继续旧履约、跨品牌证据为零、高压无资质不派工。

## 5. 从生产 Trace 到回归 Dataset

建议流程：

1. 脱敏和访问控制；
2. 按域、错误码和轨迹模式聚类；
3. 人工确认根因，不让模型自证；
4. 生成最小回归案例和 evaluator；
5. 修 Prompt、Context、工具或代码；
6. 离线实验不低于基线；
7. 预发影子流量；
8. 人工发布门禁和灰度；
9. 监控回滚条件。

LangSmith Engine 可以帮助概览和聚类，但不得自动修改生产 Prompt 或代码。任何候选修复都要通过独立 Dataset 和发布审批。

## 6. 本仓库如何验证

现有 19 项测试覆盖正常链路、异常链路、RBAC、PII、RAG、HV、审批 token、改诊补偿、Outbox、运营分层和 LangGraph 中断恢复。覆盖率约 90% 是辅助指标；比数字更重要的是关键不变量是否有直接断言。
