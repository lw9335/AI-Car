# 简历逐词追问映射

下面按商用车项目描述中的高密度词逐项拆解。每项给出“一句话回答、代码锚点、深挖方向”。

## 售后服务总控 Agent / 编排中枢

**一句话**：交互式总控负责理解员工目标并编排诊断、调度、配件和运营 Agent；人工 API 与总控共用应用服务，工单规划器只负责生成带依赖和版本的 Task Plan。

**代码**：`assistant/supervisor.py`, `assistant/runtime.py`, `application/service.py`。

**追问**：为什么不用一个大 ReAct？答上下文、权限、确定性、恢复和测试。

## Deep Agents Parent + LangGraph 子图/Workflow 分离

**一句话**：Deep Agents 适合开放式规划和工具探索；LangGraph 适合审批、Join、补偿和恢复。默认确定性 Parent 是测试替身，工厂可创建真实 Deep Agent。

**代码**：`assistant/runtime.py`、`workflows/task_planner.py`、`langgraph_flows.py`。

**追问**：哪些必须 Graph？涉及钱/库存/派工/知识发布、跨时中断、需要补偿的流程。

## Checkpoint / Interrupt / Resume

**一句话**：图在 `interrupt` 保存状态并返回待人工事项，随后用相同 thread_id 和 `Command(resume=...)` 从断点继续。

**代码/测试**：`NativeApprovalWorkflow`, `test_native_langgraph_interrupt_resume`。

**追问**：为什么还需要业务审批表？Checkpoint 是执行状态，审批表是审计事实。

## 双入口与 L0 工单记忆总线

**一句话**：领域页和总控页可以有不同 UI，但所有确认事实都落在同一 WorkOrder；`thread_id=service_request_id`。

**代码**：`WorkOrder`, API 和静态控制台。

**追问**：候选算不算 L0？它是绑定版本的领域草稿，可以存于聚合但不能当确认事实。

## 四层记忆

**一句话**：L0 业务真源、L1 领域草稿、会话摘要、PII Vault 引用；各层生命周期和访问权限不同。

**代码**：WorkOrder、DiagnosisPackage、PiiVault；会话摘要为生产扩展。

**追问**：为什么不全进向量库？业务事实需要一致性、结构化查询和审计，向量库不适合作主库。

## Task Plan / 并行扇出 / Join

**一句话**：任务有 depends_on 和状态；专家确认后 dispatch/parts 并行，人员审批和配件预占都完成才 READY。

**代码**：`TaskPlan`, `build_parallel_fulfillment_graph`, `_advance_if_fulfillment_ready`。

**追问**：一支失败？标记失败/降级，成功支线保持可补偿，不能把空结果 Join 成成功。

## REPLAN / plan_version / 旧方案冻结

**一句话**：现场不一致会冻结当前计划、补偿副作用、版本加一、清空旧确诊和候选，再重新诊断。

**代码/测试**：`report_mismatch`, mismatch test。

**追问**：迟到回调？按 plan_version 隔离，旧版本只记录审计和补偿。

## HITL 与 degraded_mode

**一句话**：专家确认、派工和敏感写均需人；工具失败应显式进入降级而不是伪造成功，重复重规划超限转人工。

**代码**：Approval、状态机、MAX_REPLANS、degraded_mode 字段。

**边界**：超时探针尚未接真实外部系统，不要说已验证真实 SLA。

## Outbox + Saga

**一句话**：Outbox 解决数据库事实和消息发布的一致性；Saga 解决跨系统动作无法整体回滚。

**代码**：`infra/outbox.py`, `report_mismatch`, `close_order`。

**追问**：补偿失败？重试、dead letter、人工任务，不能无限静默重试。

## 多模态诊断入口

**一句话**：架构支持文本/语音/图像/视频与 VIN/DTC/IoT 统一归一；样板 API 直接接收归一后的结构字段。

**边界**：未实现 ASR/CV，不要说仓库里已经识别视频。

## Mode A / Mode B

**一句话**：燃油车以 OEM 专检为故障真源；新能源以专家软件+手册 RAG 为依据，强制 HV 安全门禁。

**代码**：`DiagnosisAgent.diagnose`, `_sop`。

**追问**：为什么 VIN 优先？它是配置真源，用户可能口误或车辆改款相似。

## Hybrid RAG / BM25 / 向量 / PG / Neo4j / RRF / Rerank

**一句话**：先品牌车型硬过滤，再并行词法、语义和图扩展，RRF 融合不可比分数，最后按 DTC、权威源和车型重排。

**代码**：`knowledge/retrieval.py`。

**边界**：样板是等价小实现，生产分别替换 OpenSearch、pgvector、PostgreSQL、Neo4j。

## evidence_refs

**一句话**：不是 URL 字符串，而是包含稳定 ID、来源、章节、版本、车型和分数的结构体。

**代码**：`EvidenceRef`。

**追问**：如何防引用存在但不支持结论？做 claim-evidence entailment、专家抽检和 CitationHitRate。

## 初诊 ≠ 确诊

**一句话**：诊断能力永远输出 preliminary package；专家确认才写 confirmed_code，配件能力以它作为硬门禁。

**代码/测试**：DiagnosisAgent、PartsAgent、diagnosis tests。

## CP-SAT / 独立验证器

**一句话**：硬过滤后用 BoolVar + exactly-one + 最大化整数目标；审批后用不同代码再次校验候选和高压资质。

**代码**：`DispatchAgent._solve_cp_sat`, `verify_assignment`。

**追问**：为什么样例不像联合排班？样例验证求解和门禁机制，生产扩展为工单×资源×时段变量。

## Redis 短租约

**一句话**：用于候选确认到正式派工之间防并发抢占，不是长期事实源。

**代码**：`ResourceLeaseBook`。

**边界**：本地字典模拟 NX/PX 语义。

## BRING_BOTH

**一句话**：原厂/副厂同时预占并外带，现场选择后核销/释放，适合停工成本高且判断不确定的场景。

**代码**：`reserve_parts`。

## 指标语义层 / 禁止自由 SQL

**一句话**：NL 只映射 metric_id，服务端注入 RBAC/ABAC 与类型化参数，实际执行白名单模板。

**代码/测试**：`OperationsAgent`, free SQL rejection test。

## 事实 / 推断 / 建议 / What-if

**一句话**：四类输出在 schema 中物理分开，并带 `hypothesis_not_fact`、`pending_approval`、`what_if_not_fact` 标签。

## MCP Gateway 五池

**一句话**：车辆、知识、调度、配件、运营工具统一经过 scope、限流、熔断、参数和审计边界。

**代码**：`mcp/gateway.py`, `mcp/tools.py`。

## Tool annotations 不作授权依据

**一句话**：工具描述来自不可信配置，真正授权用服务端 principal/policy；Agent 不能自报 scope。

## LangSmith Trace 树

**一句话**：统一 metadata 把 Root/Subagent/Workflow/Tool 串成一棵树，便于定位错误路由、遗漏审批和工具静默失败。

**代码**：本地等价 `TraceRecorder`；云端需 key。

## Engine / Dataset / evaluator / 灰度

**一句话**：生产 Trace 先脱敏聚类，形成修复候选和最小回归集；离线不低于基线、预发和人工门禁后灰度，绝不自动改生产。

## Skill 晋升 Graph

**一句话**：低频变化流程保留 Skill/Agent 灵活性；稳定、高频、高风险且可形式化的套路，经评测后固化为 Graph，提高可预测性。
