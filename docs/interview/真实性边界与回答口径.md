# 真实性边界与回答口径

这份文档用来避免面试时把“架构设计、可运行样板、生产接入”混成一件事。诚实不会削弱项目，边界说清楚反而能体现工程判断。

## 可以直接说“我实现并验证了”

- FastAPI 多角色 API、JWT 登录鉴权与独立 React SPA。
- L0 `WorkOrder` 聚合、状态机、Task Plan、时间线和乐观锁契约。
- PII Vault 引用隔离（内存与 PostgreSQL 适配器）。
- 柴油/新能源诊断硬路由、HV 安全门禁。
- 小语料 Hybrid RAG：结构过滤、词法、向量相似、故障图扩展、RRF、领域重排和 evidence_refs。
- 初诊/确诊分离及专家门禁；人工接管恢复与 `degraded_mode`。
- OR-Tools CP-SAT 候选最优选择与独立验证器。
- 审批 token、短租约语义（内存与 Redis）、VIN 兼容配件、BRING_BOTH。
- LangGraph 并行 Join、现场改诊 REPLAN、原生 interrupt/resume。
- Saga 补偿、Outbox 契约（内存与 PostgreSQL 落库）。
- MCP Gateway 的 scope、参数、限流、熔断、审计和 Trace。
- 白名单指标、RBAC/ABAC 示例、What-if 分层。
- Docker Compose 服务器部署形态（api + web + postgres + redis）。
- 自动化测试套件（以当前 `pytest` 输出为准）。

## 应说“我设计了接口并用本地适配器验证”

- Kafka 事件和 Outbox relay（Outbox 已落库，默认进程内标记 delivered，未接 broker）。
- OpenSearch BM25。
- Neo4j 故障—配件图。
- DMS/ERP/WMS/IoT、地图和通知接口。

PostgreSQL 工单持久化与 Redis 资源租约已在 Compose 路径接入；无 `DATABASE_URL` / `REDIS_URL` 或 `ROADMIND_ENV=test` 时仍回退内存适配器。

## 应说“提供了可选集成点，未在无密钥环境发送真实数据”

- OpenRouter / Deep Agents Parent：配置 `OPENROUTER_API_KEY` 后走 LLM Parent；无密钥回退确定性 Parent。
- LangSmith 云端 Trace/Engine：依赖和 metadata 方案已定义，默认本地 Trace，不声称已上传企业数据。
- OEM 主机厂专检、DeepWay 专家软件：Mode 路由和 tool contract 已实现，返回值为模拟数据。

## 不要编造

- 真实公司生产用户数、工单量、准确率、降本比例、SLA 提升。
- 与北汽、福田、DeepWay 官方系统已经打通，除非你确有授权证据。
- 模型已自动确诊或自动发布知识。
- “用了 Neo4j/Redis/Kafka”如果只是 Compose 或设计。应准确说“设计并验证了端口/语义，生产替换为……”。

## 推荐回答模板

> 这个仓库是我把商用车售后业务架构落成的可运行工程样板。核心领域规则、状态机、LangGraph 工作流、Hybrid RAG、CP-SAT、审批补偿和测试是真实实现；外部 DMS/WMS、Redis、Kafka、Neo4j 和 LangSmith 云端用清晰端口隔离，默认是本地适配器，便于无凭证完整验证。生产化时替换适配器，不改领域核心。我不会把演示数据当生产指标。

## 面试官质疑“这不是玩具吗”

不要防御，按三层回答：

1. **承认边界**：默认数据和外部系统是演示适配器。
2. **指出非玩具部分**：不变量、错误路径、审批、补偿、乐观锁、证据链、可观测和测试。
3. **给出迁移路径**：Repository → PostgreSQL，LeaseBook → Redis，Outbox → Kafka，Retriever → OpenSearch/pgvector/Neo4j，MemorySaver → PostgresSaver。

这样能证明你知道“跑通 Demo”和“生产上线”之间差什么。
