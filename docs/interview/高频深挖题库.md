# 高频深挖题库（60 题）

使用方法：先遮住答案口述 60-90 秒，再打开代码验证。不要逐字背，答案中的类名和状态必须能在仓库找到。

## A. 项目与架构

### 1. 用一分钟介绍项目

RoadMind 面向商用车售后网络，把故障上报、证据初诊、专家确认、人员/工具和配件履约、现场维修、结案与知识运营串成一张可恢复工单。Parent 处理开放式理解，LangGraph 固化高风险流程，L0 WorkOrder 是真源，所有外部副作用经过 MCP Gateway。样板可离线运行，21 项测试覆盖关键不变量；外部系统通过适配器生产化。

### 2. 为什么叫“协同平台”而不是“诊断系统”？

诊断只产生初诊包，真正的车辆恢复还需要专家、人员、工位、工具、配件、物流和结案。系统核心价值是跨角色/跨系统协调，而不是单次回答准确率。

### 3. 为什么拆四个领域 Agent？

上下文、目标函数、工具权限和失败策略不同。拆分后可独立评测与降级，且不会让维修 Agent 拥有库存写权限。

### 4. 最大的架构原则是什么？

开放式推理和确定性控制分离；候选和事实分离；读建议和有副作用写操作分离。

### 5. 七层架构如何对应代码？

Role/Auth；FastAPI/Static；Parent+四 Agent；Domain/StateMachine；Knowledge/OR-Tools；MCP/Infra；Corpus。详见七层文档。

### 6. 这是微服务吗？

仓库是模块化单体，领域边界明确。先在单进程内验证不变量，再按负载、团队和数据主权拆服务，避免分布式复杂度先于业务复杂度。

### 7. 为什么用 FastAPI？

Pydantic schema、类型化 OpenAPI、依赖注入和 async 生态适合 Agent 工具/API。但业务核心不依赖 FastAPI，可在消息消费者或 CLI 重用。

### 8. 最难的部分是什么？

不是调模型，而是定义“什么时候模型结论不能继续执行”：确诊门禁、派工审批、库存门禁、改诊补偿和迟到事件隔离。

## B. 状态与记忆

### 9. L0 为什么是唯一真源？

避免四个 Agent 各自记住不同诊断/履约状态。所有确认事实和版本都由 WorkOrder 聚合控制。

### 10. thread_id 为什么等于 service_request_id？

方便把对话、图 checkpoint、Trace、事件和业务工单对齐，排障时只用一个相关 ID。

### 11. 工单 version 和 plan_version 有何区别？

version 是每次聚合修改的乐观锁；plan_version 是业务重规划版本，标识整套执行方案。

### 12. 四层记忆各自存什么？

L0 已确认事实；L1 领域候选；对话摘要用于续聊；PII Vault 保存直接标识。生命周期和权限不同。

### 13. 为什么对话摘要不能是业务真源？

摘要有信息损失和模型偏差，不能用来决定库存、派工或确诊。它只帮助恢复自然语言上下文。

### 14. 如何处理并发更新？

Repository 保存时带 expected_version；生产 SQL 用条件更新。冲突方重新读取并按业务决定重试或提示用户。

### 15. 为什么用事件时间线？

当前状态回答“现在怎样”，事件回答“为什么变成这样”。审计、补偿和效果分析都需要历史。

### 16. 状态机和 Task Plan 重复吗？

不重复。状态机约束聚合生命周期，Task Plan 描述一版执行任务及依赖；多个任务状态可以对应同一工单状态。

## C. Agent 与 LangGraph

### 17. Parent 用 Deep Agents 的价值？

适合长任务、工具探索、子 Agent 和文件/记忆中间件。项目用工厂预留真实集成，离线默认确定性实现保证可测。

### 18. 哪些流程固化为 Graph？

并行履约、诊断不一致重规划、结案门禁和原生人工审批。共同特征是高风险、重复、可形式化、需要恢复。

### 19. 为什么不把所有逻辑都放 Graph 节点？

领域规则应是普通可复用代码，Graph 负责编排。否则规则难单测、难在 API/批处理重用，并把业务事实锁进框架状态。

### 20. Interrupt/Resume 怎么工作？

节点调用 interrupt，checkpointer 按 thread_id 保存；外部得到中断 payload；人决定后用 Command(resume) 继续。

### 21. Graph checkpoint 和数据库事务如何协调？

不能假设跨两者原子。生产采用幂等节点、业务版本检查、先/后写约定和恢复补偿；敏感结果以业务库为准。

### 22. 并行 Join 的条件是什么？

候选生成图等待两节点完成；业务就绪还要求资源已人工批准且配件已真实预占。

### 23. Subagent 为什么 per-invocation？

减少跨工单上下文污染和长期内存不可控；重要结论结构化回写 L0，需要时重新从真源加载。

### 24. 怎么防止 Agent 无限循环？

任务预算、工具调用上限、同错误去重、REPLAN 上限、timeout/circuit 和人工接管。样板 MAX_REPLANS=3。

## D. RAG 与诊断

### 25. 为什么 BM25 和向量都要？

BM25 擅长 DTC/件号/术语精确命中，向量擅长自然症状语义；两者互补。

### 26. PostgreSQL 在 RAG 中做什么？

保存品牌、车型、年款、配置、版本有效期和权限过滤；这些硬条件不能只靠向量近似。

### 27. Neo4j 做什么？

表达 DTC—原因—检查项—部件—工具多跳关系，用于扩展召回和解释路径。

### 28. RRF 为什么比直接加分好？

各检索器分数范围和校准不同；RRF 用排名融合，稳定且无需把 BM25/向量分数强行同尺度。

### 29. k=60 是怎么来的？

是常见稳健默认值，降低头部排名差异的过度影响；生产应在验证集上调参，不是业务常数。

### 30. Rerank 加了什么领域信息？

DTC 精确命中、FIM/SOP 权威源和精确车型 bonus。生产可加 cross-encoder，但硬过滤不交给模型。

### 31. 如何防跨车型污染？

召回前 brand/model/version 硬过滤，评测跨车型泄漏率，证据结构带车辆范围，生成时只接收过滤结果。

### 32. evidence_refs 怎样评测？

CitationHitRate 看引用是否命中 gold；faithfulness/entailment 看证据是否支持 claim；再加专家抽检。

### 33. 无 DTC 怎么办？

输出 SYMPTOM_ONLY 和读取专检的下一步，不猜 DTC/件号。可以给安全检查但不能确诊。

### 34. 置信度 0.88 代表 88% 正确吗？

不是。当前是信息充分度启发式；要当概率必须用真实标注集校准并按故障域验证。

### 35. 初诊为什么永远要专家？

安全责任和证据完整性要求；模型置信度不能替代现场专检和责任主体。代码固定 requires_expert=True。

### 36. 新能源为何更严格？

高压误操作可能人身伤害。Mode B 强制下电/验电/挂牌和 HV 资质，远程只给检查计划。

## E. 调度与配件

### 37. CP-SAT 输入输出是什么？

输入是通过硬过滤的候选和整数目标；输出是 FEASIBLE/OPTIMAL 选择。样板 exactly-one，生产扩展工单×资源×时段。

### 38. 为什么不让 LLM 直接选工程师？

LLM 不保证组合约束，且结果难验证。LLM 可解释需求，求解器负责可满足性，人工负责最终沟通决策。

### 39. 硬约束和软约束例子？

HV 证照、品牌授权、排班是硬约束；ETA、负载均衡、成本是软目标。

### 40. 独立验证器为什么重要？

防止优化模型漏约束、数据映射错误或版本变化；敏感写前用不同代码路径重算关键条件。

### 41. Redis lease 和数据库 lock 区别？

Lease 是有 TTL 的跨进程临时占用；数据库锁通常与事务生命周期绑定。派工沟通跨较长时间，更适合 lease+审计。

### 42. 租约到期怎么办？

前端提示重新确认，不能自动认为业务取消；若正式派工已回执，以外部履约真源为准。

### 43. 配件为何不能凭症状推荐？

同症状可能多故障域，错误出库成本高。必须经过确诊 DTC/原因和 BOM/VIN 兼容。

### 44. BRING_BOTH 风险？

占库存、运输成本和现场核销差错；需客户授权、金额阈值、库存水位和释放时限。

### 45. ATP 如何算？

on_hand + 可承诺在途 - 已预占 - 安全库存，并考虑时间窗和订单优先级。

### 46. 改诊时物流已经发出怎么办？

不能简单回滚。发取消/拦截命令；失败时转退货或人工；全过程事件化，旧 plan_version 不得继续当前履约。

## F. 一致性、工具与安全

### 47. Saga 和 Outbox 区别？

Saga 协调跨系统业务补偿；Outbox 保证本地事实与消息最终一致。

### 48. 为什么补偿要逆序？

后一步通常依赖前一步资源，逆序最接近解除依赖。但真实补偿图可能不是简单栈，要按业务依赖设计。

### 49. 工具调用如何授权？

Principal scope 由服务端验证；Gateway 不信任 Prompt/annotation；敏感工具还需审批证明和资源属性检查。

### 50. 如何防重复扣库存？

幂等键绑定 order+plan_version+action，数据库唯一约束，处理成功响应缓存；重试返回同一结果。

### 51. 熔断器何时打开？

样板连续 3 次失败打开 30 秒；生产按工具类型、错误类别和窗口配置，业务错误不应计入基础设施熔断。

### 52. PII 如何处理？

直接标识存 Vault，工单只存 ref；Trace/audit 脱敏；访问需显式授权、用途和审计；保留期到期删除或匿名化。

## G. 运营、评测与生产化

### 53. 为什么禁止自由 SQL？

越权、注入、成本、口径漂移和小样本泄漏。用 metric_id+模板+类型参数+权限注入。

### 54. What-if 怎么防当事实？

schema 独立 `scenario`，强制 label 和 warning；UI 分区；下游不能把 scenario 写进事实表。

### 55. Agent 评测分几层？

单步、检索、轨迹、最终输出、业务不变量。最后一层优先级最高。

### 56. 如何从 Trace 发现遗漏审批？

按工单重建 span/event 序列，用规则 evaluator 检查 sensitive tool 之前是否存在有效 approval 事件和 token 消费。

### 57. 为什么不能让 Engine 自动修生产？

根因推断可能错，修复可能回归其他场景；需要独立 Dataset、预发、人工门禁、灰度和回滚。

### 58. 90% coverage 是否代表质量高？

不代表。它说明大部分语句执行过；关键是测试是否直接断言审批、补偿、跨品牌、高压、幂等等不变量。

### 59. 如何把样板上生产？

依次替换 PostgreSQL/Redis/Kafka/RAG 存储/真实 MCP adapters/PostgresSaver，补 IAM、密钥、SLO、压测、灾备和安全评审；领域核心和测试契约保留。

### 60. 如果再做两周，优先什么？

第一，PostgreSQL Repository+Outbox 同事务和幂等；第二，真实 Redis lease；第三，扩大评测 Dataset 与跨车型泄漏测试；第四，接一个只读 OEM/库存沙箱，而不是先增加更多 Agent。
