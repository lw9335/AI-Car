# Reference：领域模型与状态机

## 核心标识

| 标识 | 语义 | 生成/约束 |
|---|---|---|
| `service_request_id` | 工单业务主键 | `sr_` + 随机值 |
| `thread_id` | Agent/Workflow 线程 | 默认等于 service_request_id |
| `version` | 工单乐观锁版本 | 每次状态转换递增 |
| `plan_version` | Task Plan 版本 | 每次 REPLAN 递增 |
| `diagnosis_id` | 一版初诊的标识 | 专家确认必须匹配，防迟到决策 |
| `approval_id` | 审批记录标识 | 每个敏感动作单独生成 |
| `approval.token` | 演示审批令牌 | 仅 dispatcher/admin 响应可见 |
| `evidence_id` | 知识证据稳定标识 | 同时保存 source/version/section |

## `WorkOrder` 关键字段

- 输入事实：vehicle、symptom、dtc_codes、telemetry、service_mode、location。
- 隐私：`reporter_pii_ref`；直接标识保存在 PiiVault。
- 诊断：`DiagnosisPackage | None`。
- 调度：候选集合和 `selected_resource_id`。
- 配件：候选集合和 `reserved_part_codes`。
- 编排：`TaskPlan`、approvals、timeline。
- 恢复：version、replan_count、degraded_mode。

## 状态转换表

| 当前状态 | 允许下一状态 | 触发原因 |
|---|---|---|
| REPORTED | TRIAGED | Parent 完成理解与粗路由 |
| TRIAGED | DIAGNOSING | 发起证据诊断 |
| DIAGNOSING | WAITING_EXPERT / MANUAL_TAKEOVER | 初诊形成或无法自动处理 |
| WAITING_EXPERT | DIAGNOSIS_CONFIRMED / REDIAGNOSIS_REQUIRED / MANUAL_TAKEOVER | 专家决定 |
| DIAGNOSIS_CONFIRMED | FULFILLING | 启动调度/配件并行支线 |
| FULFILLING | READY_FOR_SERVICE / REDIAGNOSIS_REQUIRED / MANUAL_TAKEOVER | Join、改诊或降级 |
| READY_FOR_SERVICE | IN_SERVICE / REDIAGNOSIS_REQUIRED | 开工或现场不一致 |
| IN_SERVICE | WAITING_CLOSE_APPROVAL / REDIAGNOSIS_REQUIRED | 提交结案或改诊 |
| REDIAGNOSIS_REQUIRED | DIAGNOSING / MANUAL_TAKEOVER | 新计划重诊或超限 |
| WAITING_CLOSE_APPROVAL | CLOSED | 结案不变量通过 |
| MANUAL_TAKEOVER | DIAGNOSING / WAITING_CLOSE_APPROVAL | 人工恢复或人工结案 |

`transition()` 是唯一正式状态改变入口，非法边返回 409/抛 `InvalidTransition`。

## Task 状态

`PENDING`、`RUNNING`、`WAITING_APPROVAL`、`SUCCEEDED`、`FAILED`、`FROZEN`、`COMPENSATED`。Task 状态与工单状态不同：前者描述计划节点，后者描述聚合生命周期。

## 关键业务不变量

1. 初诊不能直接写 `confirmed_code`。
2. 配件候选要求存在专家确诊。
3. 派工需要审批 token 和独立约束验证。
4. `READY_FOR_SERVICE` 要求人员已选且配件已预占。
5. 新能源候选必须 `hv_certified`。
6. 改诊必须清空旧确诊、人员和配件，冻结旧计划。
7. 结案案例默认隔离，不直接污染生产知识。
8. 运营问数只走白名单 metric_id。
